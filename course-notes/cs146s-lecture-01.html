2 课程的 Takeaway

2.1 关注不会被 AI 替代的技能

  • Human-agent engineering 人机协同工程：专注于尚未被 AI 系统替代的技能；理解业务（business understanding）；成为技术负责人（become the tech lead）。
  • LLMs are only as good as you are：好的上下文带来好的代码；如果你自己看不懂代码库，LLM 也看不懂。

【来源：原始课件 第 10 页】

2.2 多读代码、大胆实验

  • 大量阅读与审查代码：学会分辨好的/坏的、错误的代码；培养品味（have good taste）。
  • 激进地实验：尚无既定的软件模式，大家都还在摸索；本课程会介绍许多工作流与工具——找出适合你自己的。

4 工程师视角：5 页讲清 LLM

4.1 基础：自回归的下一 token 预测

大语言模型（LLM）本质上是用于「下一 token 预测」的自回归模型（autoregressive models for next-token prediction）。

【来源：原始课件 第 14–15 页】

4.2 一次前向的四步

步骤说明
1 · 分词 Tokenize用固定词表把输入切成 token，例如「a」「for」「loop」「for」
2 · 嵌入 Embedding把 token 转成固定维度的数值向量（约 1–3K 维）
3 · Transformer 层12–96+ 层，使用自注意力机制（self-attention，Vaswani et al. 2017）
4 · 概率分布输出最可能的下一个 token 的概率分布，例如 the 0.3 / idx 0.6 / cat 0.1

图示为 token → 嵌入层 → Transformer 层（带自注意力连线）→ 下一 token 概率表中的柱状结构。

【来源：原始课件 第 16 页】

4.3 训练过程：三个阶段

阶段做法规模 / 示例
Stage 1 自监督预训练在多样的公开数据源上教会模型「语言的概念」数千亿到万亿+ token（语言与代码）；Common Crawl、Wikipedia、StackExchange、公共 GitHub 仓库。类比：写 for 循环 →「这可能用在某段代码里」
Stage 2 监督微调教模型遵循指令高质量、精心整理的 prompt-response 对（「克罗地亚首都是什么」→「萨格勒布是首都」）；数万到数十万对。类比：写 for 循环 →「好的，这是一个 for 循环…」
Stage 3 偏好调优让模型输出对齐人类偏好（有用性、正确性、可读性）对同一 prompt 收集成对输出，训练奖励模型预测偏好输出；数万到数十万人工标注比较。类比：写 for 循环 →「for idx in range(10):」

【来源：原始课件 第 17 页】

4.4 推理模型与规模

  • 推理模型（Reasoning models）：用思维链推理轨迹扩展训练；集成工具使用；对推理步骤收集人类偏好；用强化学习学会评估推理轨迹、回溯等。
  • 规模：GPT-3 / Claude 3.5 Sonnet 约 175B 参数；LLaMA 3.1 为 405B；GPT-4 据报道 1.8T。

【来源：原始课件 第 18 页】

4.5 实践中的优势与局限

内容
优势 Strengths专家级代码补全；代码理解；代码修复
幻觉 Hallucinations生成不存在/过时的 API——可用稳健的上下文工程缓解
上下文窗口限制约 100–200K tokens，但并非每个 token 都等价
延迟 Latency每个请求数秒到数分钟，取决于任务——据此规划与委派
成本 Cost最好的模型每百万输入 token 约 $1–3，每百万输出 token $10+

【来源：原始课件 第 19 页】
