## 1. 连接器与工具调用 {#connectors}

没有连接器时，你可能复制一封邮件到聊天工具，让它修改，再把结果粘贴回邮件。连接器把 AI 应用与外部服务连起来，让它能直接检索材料，某些情况下还能替你更新或发送内容。

因此需要分清两种能力：**读取信息**与**采取行动**。读取日历不等于可以修改日历，整理草稿不等于可以发送邮件。具体权限由服务、凭据与宿主系统控制。

模型内部仍然生成 token。区别在于输出有时是一份符合工具接口的结构化请求，由应用解析执行，再把结果交回模型。例如：

~~~json
{
  "tool": "get_weather",
  "arguments": {"city": "Shanghai", "date": "2026-11-19"}
}
~~~

这是解释机制的自编格式，不是某个真实接口。模型生成这段文本本身不会自动获取天气；宿主系统必须识别请求、检查参数与权限、调用工具。

**课件依据：第 3—10 页。**

课件介绍 **MCP（Model Context Protocol）**作为连接模型应用与工具的协议语境。需要补充：不是所有工具调用都使用 MCP；MCP 也不等于权限系统或智能体本身。应用可以通过其他 API 接入工具，安全边界仍要由程序和服务实现。

**课件依据：第 11 页；协议范围为技术澄清。**

## 2. 智能体的七个要素 {#anatomy}

课件把一个明确规格的智能体拆成七部分。以「协助安排一次团队聚餐」为例：

| 要素 | 要回答的问题 | 示例 |
| --- | --- | --- |
| Goal 目标 | 最终要达成什么 | 形成所有参与者可接受的安排 |
| Context 上下文 | 必要背景是什么 | 参加者、候选时间、地点条件 |
| Tools 工具 | 能调用什么 | 日历查询、消息草稿 |
| Permissions 权限 | 哪些动作允许、范围多大 | 只查询相关日程，发送前复核 |
| Memory 记忆 | 跨步骤保留什么 | 已确认偏好与回复 |
| Actions 动作 | 怎样推进任务 | 查询、比较、提议、记录回复 |
| Stopping conditions 停止条件 | 何时完成或交回人处理 | 确认成功，或三轮仍无共同时间 |

**课件依据：第 12—13 页。**

这个表延续了第 2 讲的任务说明书，但增加了行动边界。目标和权限不能混写：用户想「安排聚餐」，不代表系统自动获得所有人的私人日程与任意发送消息的能力。

一个良好停止条件也不只是「直到做好」。它可以包含时间、费用、尝试次数、完成证据和需要升级给人的情况。

## 3. 分析—行动—观察循环 {#loop}

基本循环是：

~~~text
分析当前状态 → 选择动作 → 宿主执行工具
      ↑                         ↓
      └──── 观察结果并更新状态 ───┘
                   ↓
          达成目标或触发停止条件
~~~

例如模型想根据天气建议穿衣：先判断需要天气数据，发出查询，读取结果，再形成建议。如果结果缺少城市、日期或查询失败，它还应重新分析，而非当作成功继续。

智能体与一次工具调用的差别，在于它可能依据反馈连续决策。工具成功返回只是一次动作的完成，不代表整体任务已经实现。

**课件依据：第 15 页。**

**补充例子：**任务是把会议记录转成待办。工具返回「已创建三项任务」，下一步应检查负责人、日期与重复项；如果三项任务都有错误负责人，接口调用成功，业务任务仍然失败。

## 4. 人在循环中的位置 {#humans}

Human in the loop 不是一句「人会看着」就设计完了。课件提出两个问题：人何时知道进展，人何时能控制进展？

| 环节 | 人可以看到什么 | 人可以决定什么 |
| --- | --- | --- |
| 规划 | 目标、资料、拟执行动作 | 修改任务边界 |
| 执行中 | 已完成步骤、失败与成本 | 中断、调整、补充信息 |
| 高影响动作前 | 完整收件人、内容和后果 | 是否执行 |
| 结束后 | 成果、证据、未解决事项 | 接受、重做或回滚 |

这些位置随任务而变。低风险、可逆的小动作可以自动完成；公开发送、不可逆修改等动作则需要更具体的控制设计。检查机会必须发生在能改变结果的时候。

**课件依据：第 16 页；表格为补充展开。**

## 5. 大象与金鱼工作流 {#elephant}

课件介绍 Dave Rensin 的 **Elephant and Goldfish** 模式，用两个角色解决「探索对话很丰富，但交接文档不完整」的问题。

**大象**保留长对话，负责访谈需求、理解业务、整理详细任务说明与质量标准。它知道许多背景，但不能只把背景留在聊天里。

**金鱼**从全新上下文开始，只读任务说明与被明确引用的材料，检查是否能理解并独立执行。若仍有关键问题，大象就补充文档，再换一条干净上下文重测。

**课件依据：第 17—21 页。**

| 步骤 | 产物 | 要避免的问题 |
| --- | --- | --- |
| 需求访谈 | 目标、限制与取舍 | 用户没说清，模型自行猜 |
| 写任务说明 | 可独立阅读的规格 | 文档依赖旧聊天的默契 |
| 新读者检查 | 明确的缺口清单 | 审查者也继承同样假设 |
| 修订与再检查 | 更新的规格 | 只在聊天里口头修正 |
| 人审后实施 | 经确认的执行依据 | 把「没有提问」误当成充分验证 |

课件给出数页任务描述与质量标准作为复杂项目示例，不必把页数当作通用要求。简单任务可以很短，关键是信息足够而且能验收。

**补充提醒：**金鱼没有问题，也可能只是没发现问题。它检验文档的自足性，不证明需求正确、实现安全或项目必然成功。

## 6. 最小权限、风险与可逆性 {#safety}

课件要求对智能体问「最坏会发生什么」，并用三类情境练习：报修照片可能暴露其他照片，求职助手可能发出不合适的消息，磁盘清理可能误删重要文件。

核心是 **最小权限（least privilege）**：只提供完成任务所必需的最小资源范围和操作能力。要求只清理 Downloads，就不应开放整台电脑的永久删除权限。

**课件依据：第 24—28 页。**

| 原始设计 | 可以缩小的边界 | 可恢复性 |
| --- | --- | --- |
| 查看全部照片并自动发报修邮件 | 只提供选中的照片，先形成草稿 | 草稿比已发送邮件更易修正 |
| 自动回复所有求职消息 | 限定联系人、主题与内容，复核后发 | 事前检查比事后道歉可靠 |
| 扫描并永久删除任意文件 | 指定目录，先列清单、再可恢复移动 | 保留恢复路径 |

风险矩阵把可能性与严重程度放在一起评估。**可逆性**会显著影响严重程度；同样的误判，修改一个可撤销草稿与永久丢失文件的后果不同。

课件也提醒，AI 的失效概率缺少稳定历史数据，估计通常不精确。矩阵帮助讨论和确定优先级，不能把主观评分伪装成精密概率。

**课件依据：第 28—29 页。**

## 7. 练习与自测 {#practice}

**补充练习：**为「每周整理公开课程资料」写一份七要素规格。限定只读取指定网页，输出笔记草稿，遇到缺失讲义注明范围，单次运行设定时间与页面数上限。再让一个不看起草过程的新会话检查它。

<details><summary>模型生成工具调用后，动作就已经发生了吗？</summary><p>没有。宿主系统还需要解析、检查并执行。模型提出动作与程序授权动作是不同阶段。</p></details>

<details><summary>为什么停止条件是智能体设计的一部分？</summary><p>智能体会连续决策，没有明确边界就可能重复尝试、浪费预算或扩大任务。停止条件定义成功证据和无法继续时的交接方式。</p></details>

<details><summary>大象与金鱼分别解决什么问题？</summary><p>大象把复杂需求收集并写成明确规格；金鱼通过没有旧背景的新视角检查规格是否自足。最终正确性仍需人和实际验收证据。</p></details>
