## 1. 读懂 token 与时间报告 {#usage}

课件用一份 Claude Code 用量报告说明：眼前看到的几段对话，不是系统全部工作量。提示、历史、工具描述、文件和工具返回数据都会参与资源消耗。

| 指标 | 怎样理解 | 容易误解的地方 |
| --- | --- | --- |
| Input tokens | 模型处理的输入量 | 不只用户手打的文字 |
| Output tokens | 计入输出的生成量 | 可能包括工具请求或推理相关用量，规则因服务而异 |
| Cache read / write | 缓存命中或写入的用量 | 必须按对应计费类别区分 |
| API duration | 一次或多次请求所耗时间 | 可能含网络等待，不只模型计算 |
| Wall duration | 现实中经过的时间 | 还可能包含用户阅读、思考和暂停 |
| 工具 / 技能上下文开销 | 提供工具或指令所占输入 | 元数据与完整指令可能按不同方式加载 |

**课件依据：第 4—14 页。**

这些指标怎样统计，取决于应用和服务。并行请求的 API 时间之和可能大于用户实际等待；界面计数也不一定等于最终账单。因此要先看报告的定义，再解释数值。

产品菜单与命令可能变化，学习重点是读懂字段的含义，而不是记住某张截图的位置。

## 2. 缓存复用了什么 {#cache}

长任务经常重复使用同一段前缀，例如系统指令、工具定义或一份文档。**Prompt caching** 可以复用这类相同输入已有的部分计算状态，减少重新处理的成本。

课件用注意力计算类比解释缓存。更精确的理解是：缓存可以复用固定前缀对应的中间状态；它不是把整份文档压成一份永远有效的「答案」，也不是所有后续注意力计算都不用做。

| 概念 | 缓存什么 | 是否仍可能生成新回答 |
| --- | --- | --- |
| 提示前缀缓存 | 相同前缀的可复用计算状态 | 是 |
| 输出 / 响应缓存 | 已有请求的成品回答 | 命中时可能直接复用 |
| 检索存储 | 文档与可搜索索引 | 检索后仍需生成 |

这是补充的概念区分。具体缓存粒度、有效期、写入和读取价格由服务决定。

**课件依据：第 10—12 页；缓存类别区分为技术澄清。**

组织稳定前缀、减少不必要变动，有时有助于命中。但不能为了缓存而保留大量无关内容：便宜地处理无关输入，也不等于对任务有用。缓存还不会提高来源的真实性。

## 3. 估算完整工作流的费用 {#budget}

以下是教学用的简化公式。把普通输入、缓存读取、缓存写入和输出视为互不重复的计费类别：

$$
C_{\mathrm{model}}
=\frac{N_i p_i+N_r p_r+N_w p_w+N_o p_o}{10^6}.
$$

其中 $$N$$ 是 token 数，$$p$$ 是对应类别每百万 token 的单价。某些服务不单独收写入费，或者字段定义不同，实际应按账单规则调整，不能重复计费。

**假设算例：**一次任务有 10,000 个普通输入 token、40,000 个缓存读取 token 和 2,000 个输出 token；假设单价分别为 1、0.1、4 个货币单位 / 百万 token，忽略其他费用：

$$
C=0.01+0.004+0.008=0.022.
$$

这不是任何厂商当前价格，只演示计算。若同一流程平均需要重试 3 次，总费用就可能变成单次的数倍；还应加上搜索、执行环境、存储和人工复核等成本。

比较方案时可统计：

$$
C_{\mathrm{per\ accepted\ task}}
=\frac{\text{总运行费用}}{\text{通过验收的任务数}}.
$$

低单价模型如果不断返工，未必比单次更贵但稳定成功的模型便宜。这个指标也要与错误后果一起看，不能只用经济效率评价重要决策。

**本节公式和算例为补充推导，承接课件第 5—14 页的用量分析。**

## 4. 按任务选择模型 {#model}

课件反对简单把「更大」当成「总是更合适」。模型的任务表现、价格、延迟、可用工具与输出约束都要考虑。小模型通常有成本或延迟优势，但具体部署下并非无例外。

对于串行流程，可粗略写成：

$$
T_{\mathrm{total}}
\approx \sum_k T_{\mathrm{model},k}
+\sum_j T_{\mathrm{tool},j}
+T_{\mathrm{retry}}.
$$

如果有并行步骤，真实等待时间更接近关键路径，而不是所有步骤时长的总和。

**课件依据：第 17—18 页；时间公式为补充。**

### 例一：教学助手

课件把流程分成输入检查、回答生成和输出检查。三步不一定需要同一模型：

- 简单明确的限制，可以先考虑规则检查。
- 需要解释与教学判断的回答，适合更强的能力。
- 输出检查要独立验证目标，不能只看语气是否友善。

课件用「连续代码不超过某行数」作输出限制示例。这个规则易测，但只是教学边界的代理：两行也可能直接给出答案，多行伪代码也可能仍有教学价值。

**课件依据：第 19—20 页；代理指标局限为补充。**

### 例二：组织资料问答

生成者从资料库取依据，检查者核对答案与引用是否匹配。检查者不能只是「请评价这段话是否不错」，还要拿到来源。

更多检查环节会增加成本，也可能引入新的错误。应通过测试验证其是否发现实际失败，而不是默认多一个模型就更可靠。

**课件依据：第 21—22 页。**

## 5. API 密钥与泄漏 {#keys}

API 让程序直接使用模型服务。**API key**是与调用权限和计费账户相关的凭据，使用它的程序可能把费用记在对应账户上。

课件对比两类付费方式：工具运营方统一支付，或使用者提供自己的调用凭据。无论哪一种，用户都需要知道数据和密钥会经过谁的系统，费用由谁承担。

**课件依据：第 23—25 页。**

课件用一个网页翻译器演示泄漏：若服务密钥写进浏览器可下载的 HTML 或 JavaScript，访问者就可能直接看到并复制。混淆代码或隐藏按钮不能让浏览器中的秘密真正保密。

| 位置 | 为什么有风险 |
| --- | --- |
| 前端代码与静态网页 | 访问者可以下载或查看 |
| 公开代码仓库 | 提交历史也可能保留旧凭据 |
| 日志、截图与聊天 | 复制传播后难以收回 |
| 不可信的第三方工具 | 可能保存或滥用凭据 |

**课件依据：第 26—31 页。**

**补充实践：**长期服务密钥保存在受控后端或密钥管理系统中，浏览器请求自己的后端，再由后端执行授权、限流与服务调用。即使密钥没泄漏，一个对外开放且无限调用的代理也可能产生滥用费用。

已经公开的密钥应撤销并轮换，检查异常使用；仅从当前文件里删除，不等于旧副本失效。本篇不展示课件截图中的任何凭据字符串。

## 6. 环境与社会成本 {#environment}

课件把费用扩展到电力、用水、排放与数据中心对社区的影响。它还列举文本、图片、视频、推理和长上下文的若干估算，说明任务形态与计算配置会显著改变成本。

理解这些数字时，要问：

- 测量对象是单个请求、平均用户还是整个服务？
- 是否包含闲置设备、网络、训练和基础设施？
- 水与电的边界是直接消耗还是还包含供应链？
- 请求长度、生成长度、硬件、地点与时段是否相同？

因此本笔记不把课件中的单次估算转成「所有 AI 问一次固定耗多少水电」的结论，也不把不同研究的倍数直接相乘。

**课件依据：第 15—16 页。**

课件第 32—33 页用数据中心相关时事引导讨论。这里保留的学习问题是：成本由谁支付、收益由谁获得、地方资源与居民意见如何进入决策。具体选举数字和人物结论未在本篇独立核验，因此不作为新闻事实复述。

## 7. 练习与自测 {#practice}

**补充练习：**选择一次真实的多步任务，记录各步输入、输出、缓存、时间、重试与是否通过验收。再只改变一个因素，例如缩短背景或替换一个简单步骤的模型，比较质量与总成本。

<details><summary>缓存命中后，模型就不需要再阅读或生成了吗？</summary><p>仍需进行后续计算与生成，只是复用一部分已有状态。它不同于直接返回缓存答案，也不证明模型充分利用了资料。</p></details>

<details><summary>为什么不能只比较每百万 token 单价？</summary><p>不同方案的输入长度、输出长度、重试次数、检查开销和验收通过率不同，最终每个合格任务的成本可能反过来。</p></details>

<details><summary>静态网站里把密钥变量改名，再压缩代码，安全吗？</summary><p>不安全。只要浏览器必须取得长期密钥才能调用，使用者就有机会提取它。应把长期凭据留在受控服务端，并限制代理调用。</p></details>
