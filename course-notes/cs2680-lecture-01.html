7 Part I — AI 系统：与传统计算机系统的差异

7.1 什么是 AI 系统？

AI 系统包含许多活动部件：调度与编排、状态管理、通信、缓存、容错、安全、可观测性……（注：AI 系统是个宽泛概念，本课程狭义聚焦于 LLM 系统。）

AI / MLAI Systems
核心问题「该用什么模型？/ 我该如何设计模型？」「如何大规模地训练和服务它？」
典型做法选一个模型，写个 Python 脚本解决任务追求：GPU 利用率最大化（性能）、资源浪费最小化（效率）、停机时间最小化（可靠性）、碳足迹更低（可持续性）
优化目标准确率与能力（accuracy / capability）性能、效率、可靠性、可持续性

【来源：原始课件 第 28 页】

7.2 为什么要关心 AI 系统？

「这里正是能力（capability）转化为产品（product）的地方——而且它比 AI 本身更难。」

  • 关键数字基础设施（critical digital infrastructure）
  • 理解模型设计、设计更好的产品、更多就业机会

【来源：原始课件 第 29 页】

7.3 AI 系统的六大差异

差异维度要点
① 计算（compute）异构计算：CPU 负责分词、内核启动、数据搬运、工具调用；GPU 负责矩阵乘法；混用不同代 GPU 与 xPU。 计算阶段分明：prefill 受算力限制（compute-bound），decode 受显存带宽限制（memory-bandwidth-bound）；同一部署会遇到不同瓶颈（算力/带宽/容量）。 执行时间不可预测：取决于输出长度，使调度复杂化。
② 非确定性计算（non-deterministic compute）浮点加法不满足结合律（每次运算都有舍入），传递性也失效；「蝴蝶效应」：矩阵乘中小数点后第 7 位的偏移就会翻转下一个 token。 来源：运行时（warp/block 调度、访存顺序、异步流、batch size）、软件（融合乘加 vs 两次运算、自动调优、次正规数）、硬件（CUDA vs 张量核、Hopper FP8 vs Blackwell 微缩放 tile）。 结论：近似计算是可接受的（approximate computing is acceptable）。
③ 内存、存储与通信状态巨大：模型权重 GB~TB 级；KV-cache 每 token 数十~数百 KB；prefix cache 跨请求复用 KV；数据搬运成为瓶颈。 多 GPU 通信：流水线/张量/专家/上下文并行；集合通信 NCCL、UCCL；拓扑 NVLink、以太网/InfiniBand；CPU 与内核旁路 RDMA。
④ 快速演进的模型与负载模型架构快速演进：MHA、GQA、MLA、NSA、线性注意力…… 负载快速演进：多轮对话（交互式、延迟敏感）、问题求解（长输出推理）、RAG（检索文档、长上下文）、智能体（长上下文、prefix-cache 关键、路由与负载均衡）。 思路：让模型适配硬件 → 为模型架构设计硬件。
⑤ 可靠性、功耗与能耗可靠性：9% 年故障率（AFR）、50,000 小时 MTBF；在 16K GPU 集群中平均每 3 小时就有一块 GPU 故障。 功耗能耗：CPU 100–300W，GPU 700–1000W，每台服务器 4–8 块 GPU；服务器功耗 800W→6,000W（约 8 倍）；如何避免功率波动。

【来源：原始课件 第 30–34 页】

本部分小结 AI 系统之所以难，在于它同时叠加了：异构且非确定的计算、巨大的有状态内存、多 GPU 通信、快速变化的模型与负载，以及高故障率与高功耗——这些都是传统系统课里不常同时出现的约束。

8 Part II — 智能体 AI 系统：什么是智能体，为何它是系统问题

8.1 什么是 AI 智能体？

定义：AI 智能体是一个自主软件系统，它使用 AI 模型来推理目标、调用外部工具，并执行多步动作，直到任务完成。智能体内部包含 Memory（记忆）、LLM（推理与规划）；它通过 Action / Observation 与环境（Environment）交互。

五步循环含义
1. plan 规划把任务拆解为子步骤
2. act 行动调用外部工具（API、数据库）
3. observe 观察解读工具返回的结果
4. adapt 调整根据新信息修订计划
5. deliver 交付返回最终结果

【来源：原始课件 第 36 页】

8.2 为什么需要 AI 智能体？

「LLM 是一台奇怪的计算机：同时超人又无能。」

超人之处（Superhuman at）出人意料的弱点（Surprisingly weak at）
海量事实知识的记忆持久记忆（persistent memory）
语言能力可靠地理解上下文
模式匹配避免幻觉
生成代码知道自己不知道什么
跨多个领域操作安全性与对抗性输入

【来源：原始课件 第 37 页】

8.3 智能体是一种新型计算机

传统计算机→智能体（Agent）
CPU→LLM
RAM / 工作内存→上下文窗口（Context window）
外设（Peripherals）→工具（Tools）
操作系统（OS）→智能体外壳（Agent Harness）
应用程序（Application）→智能体（Agent）
核心观点 「LLM 不止是一颗更聪明的 CPU」——它是一台新型的可编程计算机，拥有完全不同的编程模型与失效模型（failure model）。

【来源：原始课件 第 38 页】

8.4 为什么智能体是系统问题？

智能体有许多轮次（many turns），其关键路径横跨 GPU、CPU、存储、网络与外部服务。

流程对比
传统 LLM 服务request（请求） → inference（推理） → response（响应）
智能体服务infer（推理） → tool（工具） → infer → tool → retrieval（检索） → infer → …
  • 步骤之间存在依赖关系（dependencies）
  • 各步骤延迟高度可变（highly variable step latency）
  • 阻塞 / 等待工具（blocking / waiting on tools）
  • 状态快速增长（rapidly growing state）
  • 并发与投机（concurrency & speculation）
  • 轨迹中任何地方都可能失败（failures anywhere in trajectory）

【来源：原始课件 第 39 页】

层级内容
Application / User（应用/用户）顶层

Tools（工具，外部环境）web · files · APIs · humans（网页·文件·API·人）
Systems（系统侧）scheduling · caching（调度·缓存）

右侧协同轴线Agent ↔ Serving ↔ Hardware 三者协同设计（co-design）

【来源：原始课件 第 40 页】

8.6 我们到底在优化什么？

关键论断 「吞吐量（Throughput）对于智能体来说是错误的目标。」

优化目标：最大化 task success（任务成功率），受限于 latency（延迟）、cost（成本）、resources（资源）、reliability（可靠性）、security（安全）。

有用但不充分（Useful, but insufficient）我们实际优化的（What we actually optimize）
TTFT / TPOT（首 token 延迟 / 每 token 延迟）任务成功率 / 准确率（task success / accuracy）
工具调用延迟（tool-call latency）端到端延迟（end-to-end latency）
GPU 利用率（GPU utilization）每个任务的 token 数（tokens / task）
每个成功任务的成本（$ / successful task）★
每个成功任务的能耗（Energy / successful task）★

注解：每秒 token 数更多，仍可能意味着一个更慢、更贵的智能体。

【来源：原始课件 第 41 页】

8.7 智能体系统引入的新系统问题

智能体负载的每一项属性，都对应本课程要研究的一个系统问题：

智能体负载属性→ 对应的系统问题

分支推理（Branching reasoning）投机执行（speculative execution）

外部副作用（External side effects）安全与隔离（security & isolation）
长时运行任务（Long-running tasks）检查点与容错（checkpointing & fault tolerance）

【来源：原始课件 第 42 页】

8.8 可观测性是一等公民

对智能体而言，分布式追踪（distributed trace）变成了一个嵌套的轨迹（nested trajectory）：

嵌套层级（从外到内）
Session（会话） → Turn（轮次） → Agent step（智能体步骤） → Model request（模型请求） → Tool call（工具调用） → Tool result（工具结果） → Agent step → Subagent（子智能体） → …
金句 「你无法优化你无法观测的东西。」（You cannot optimize what you cannot observe.）

【来源：原始课件 第 43 页】

10 附录 A：AI 智能体 / 助手 / 机器人 对比

维度AI 智能体（Agent）AI 助手（Assistant）机器人（Bot）
目的 Purpose自主、主动地执行任务协助用户完成任务自动化简单任务或对话
能力 Capabilities复杂的多步动作；学习并自适应；自主决策响应提示；可推荐动作，但由用户决定遵循预定义规则；学习能力有限；基础交互
交互 Interaction主动、目标导向被动、响应用户请求被动、响应触发或命令

关键差异：自主性（Autonomy）、复杂度（Complexity）、学习（Learning）。

  • 自主性：智能体为达成目标自主运行与决策；助手需要用户输入与指引；机器人遵循预设程序规则。
  • 复杂度：智能体处理复杂任务与多步工作流；助手与机器人适合更简单的任务与交互。
  • 学习：智能体通过机器学习随时间自适应；助手可能略能学习；机器人几乎不学习。
