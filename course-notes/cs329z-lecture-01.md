## 1. 课程定位：模型、系统与实践 {#course}

CS329Z 把两个视角放在一起：模型研究者关心训练、提示、对齐和评估，系统工程师关心工具、接口、环境和可靠软件。构建真实智能体，需要同时理解这两方面。

课程的路径是先认识 LLM、检索增强生成、工具调用、智能体架构与记忆，再进入多智能体、优化、数据、评估、安全和具体应用。作业与项目要求亲手搭建、测量并解释系统，不能只停在框架调用层。

| 学习对象 | 核心问题 |
| --- | --- |
| 模型 | 给定输入时，它能做什么、容易怎样错？ |
| 系统 | 用哪些组件、怎样控制状态与动作？ |
| 数据 | 用什么示范、经验和上下文支持任务？ |
| 评估 | 如何证明改进确实有效，并发现失败？ |

课件还提醒：AI 可能提高作业成品质量，却让使用者跳过理解和调试的训练。课程希望你用 AI 促进学习，而不是提交自己无法解释的结果。课堂展示的学习研究属于特定实验，不能把其数字当作任何人使用 AI 都会下降相同比例的定律。

**课件依据：第 4—17 页。**选课、作业与资源安排可能调整，以[官网 Logistics](https://cs329z.stanford.edu/logistics.html)为准。

## 2. 智能体不是 LLM 时代才出现 {#history}

Agent 的核心含义是「能行动的实体」。在现代聊天模型出现之前，人工智能已经长期研究感知、决策、协作与环境反馈。

| 阶段 | 课件中的代表思想 | 延续到今天的问题 |
| --- | --- | --- |
| 早期分布式与符号系统 | Actor、任务协商、心智社会 | 多个组件怎样承担任务和通信？ |
| 1990 年代智能体理论 | 自主性、社会性、反应性、主动性 | 何时响应环境，何时主动推进目标？ |
| 强化学习 | 智能体—环境循环、奖励、策略 | 动作怎样影响后续状态和回报？ |
| LLM 时代 | 上下文学习、语言推理、工具使用 | 怎样让通用模型进入任务反馈循环？ |

传统教科书把智能体描述为通过传感器感知、通过执行器行动的系统。对软件智能体而言，传感器可以是网页、文件和工具结果，执行器可以是 API、终端命令或界面操作。

LLM 带来的变化，是语言成为较通用的任务接口：模型能够读懂要求、利用上下文、生成计划，并选择工具。但「底层模型更强」与「完整智能体更可靠」仍是不同问题，工具与环境会增加新的失败来源。

课件用 MRKL、ReAct、BabyAGI、AutoGPT 等展示这一演进。记住各个发布日期不是重点，理解「语言模型如何接入外部能力」更有价值。

**课件依据：第 18—27 页。**

## 3. 智能体的五个核心部分 {#anatomy}

课件把一个 LLM 智能体拆为五部分：

| 部分 | 中文理解 | 在系统中承担什么 |
| --- | --- | --- |
| LLM core | 语言模型核心 | 理解上下文，提出回答或动作 |
| Planning & reasoning | 规划与推理 | 分解目标，选择下一步，更新内部状态 |
| Memory | 记忆 | 保留事件、知识或可复用技能 |
| Tools | 工具 | 检索、计算、执行代码、操作文件等 |
| Environment | 环境 | 动作发生并产生反馈的外部世界 |

环境可以是网页、桌面系统、手机应用、游戏、数据库等。工具是进入环境的接口，环境是动作的实际对象，二者不应混为一谈。

~~~text
目标与当前状态
      ↓
模型结合记忆进行判断
      ↓
提出动作 → 系统检查并执行工具 → 环境变化
      ↑                           ↓
      └─────── 接收观察结果 ───────┘
                   ↓
             完成或触发停止条件
~~~

上图是对课件结构的文字重绘，补入了工程上必要的检查与停止边界。模型生成「读取文件」请求，与文件真的被正确读取，是两个阶段；生成「任务完成」也不能代替完成证据。

**课件依据：第 29—34、44、50、53 页。**

## 4. 推理、行动与反馈怎样配合 {#reasoning}

课件将人类推理、LLM 中间生成和智能体内部状态更新区分开。模型生成一段计划，可以帮助后续决策，但不应由此认定它具有与人完全相同的心理过程，或这段文本忠实暴露了全部内部计算。

### ReAct：用观察修正规划

只推理不行动时，模型可能基于错误前提连续推导，越写越像正确答案。ReAct 把推理与工具动作交替组织：先判断缺什么信息，再查询，根据实际结果调整下一步。

课件中的检索案例展示：初次搜索结果不够明确，系统再改用消歧后的词条，而不是继续猜。这体现了**反馈决定下一步**，并非「一次把计划写得很长」。

| 方式 | 优势 | 主要限制 |
| --- | --- | --- |
| 直接回答 | 路径短、成本低 | 可能缺少外部依据 |
| 只做中间推理 | 有助于分解任务 | 错误前提仍可能自洽 |
| 推理与行动交替 | 可以依据新证据调整 | 工具错误、延迟与成本增加 |

**课件依据：第 33—37 页。**课件中的实验对比支持特定任务上的观察，不证明 ReAct 在任何任务上都优于简单流程。

### Self-consistency：多条路径的答案聚合

自洽性方法生成多条推理路径，再根据最终答案的一致程度做选择。它利用多个样本降低单次偶然错误，但前提是候选有实际多样性；如果所有路径共享一个错误前提，多数一致仍可能错。

### Reflexion：把失败压缩成经验

Reflexion 根据任务反馈生成反思文本，保存为未来尝试的提示。这里常见的更新对象是文本记忆，而不是每次都更新模型权重。

好的经验应能指向下次可改变的动作，例如「先检查单位」，而不是一句笼统的「以后更认真」。反思也可能错，因此不宜把每次失败后的自我解释都永久保存为真理。

### 辩论与协调

课件还介绍多智能体讨论，以及由 orchestrator（协调者）分配任务的结构。协调者可以把文件读取、网页访问、代码分析与执行分给不同组件，再汇总结果。

这些结构增加了角色分工，也增加通信、重复工作和错误传递。不能仅用角色数量判断质量，应看它们是否提供了有用的独立信息或检查。

**课件依据：第 38—43 页；限制与经验写法为补充理解。**

## 5. 三类长期记忆 {#memory}

上下文无法容纳所有事件；即便能放下，模型也未必能有效提取关键经验。记忆设计的任务是决定保存什么、怎样写入、何时读回。

课件按内容划分三类记忆，这与文件、数据库、向量库等存储技术属于不同维度。

| 类型 | 保存什么 | 写入与读取的直觉 | 自编例子 |
| --- | --- | --- | --- |
| Episodic 情节记忆 | 曾发生的经历 | 记录事件，按相关性等信号取回 | 上次导入文件因编码错误失败 |
| Semantic 语义记忆 | 归纳后的知识 | 从事件提炼事实，再检索 | 此项目的源文件使用 UTF-8 |
| Procedural 程序性记忆 | 可执行或可复用技能 | 保存步骤、代码或技能，再匹配使用 | 读取、转换并验证编码的脚本 |

课件以 Generative Agents 展示事件与知识记忆，以 Voyager 的代码技能库展示程序性记忆。学习重点是从经历中提取可复用信息，而不是让每次任务都背负完整历史。

**课件依据：第 45—49 页。**

**补充提醒：**归纳会丢失上下文，旧经验也可能失效。比如某一次导入失败，不足以推出所有文件都有相同编码。因此实际系统还需要来源、时间、适用范围以及更新或删除机制。

## 6. 工具、RAG 与 MCP {#tools}

### 工具能力不在模型权重里凭空执行

课件用 Toolformer 说明模型可以学习何时选哪个 API、怎样填参数和利用返回结果；Gorilla 则展示面向大量 API 的工具选择问题。

工具调用可以拆成：

1. **选择**：从当前可用工具及描述中选一个。
2. **填参**：把任务需求转成类型明确的参数。
3. **校验**：检查结构、字段、范围和权限。
4. **执行**：在受控环境运行，把真实结果带回上下文。

课件展示读取文件时，参数结构合法只是其中一步。路径类型是字符串，不等于路径存在、允许访问，或内容符合预期。

**课件依据：第 51—52、58 页。**

### RAG：把外部证据带进生成

RAG 的基本过程是检索资料、把相关内容加入上下文，再生成回答。它可以提供更新信息与任务专用知识，但资料仍可能错误，检索仍可能漏掉关键段落。

一次固定的「检索 → 回答」可以只是工作流；如果模型根据证据决定继续搜索、改写查询或调用其他工具，才有了更动态的控制过程。

**课件依据：第 57 页。**

### MCP：统一接入方式

MCP 用标准化协议连接 AI 应用与外部数据、开发或生产力工具，使宿主与工具服务之间有共同接口。它解决接口互通的一部分问题，不自动决定智能体目标、规划策略或用户授权。

不是所有工具调用都使用 MCP。即便通过 MCP 接入，工具结果仍需校验，外部内容仍不能当成新的高权限指令。

**课件依据：第 59 页；协议与授权的区分为技术澄清。**

## 7. 工作流与自主智能体 {#architecture}

复合 AI 系统（compound AI system）把 LLM 与检索器、工具、执行器或优化器等组件组合起来。它既包括固定工作流，也包括动态智能体。

关键差异是：**下一步由预写代码决定，还是由模型根据状态动态选择？**

| 结构 | 主要控制方式 | 适合的情况 |
| --- | --- | --- |
| 工作流 | 代码固定步骤与分支 | 路径清楚、需要可预测性 |
| 智能体 | 模型决定部分下一步动作 | 路径不确定、需要探索与反馈 |
| 混合结构 | 固定框架中留出局部自主性 | 既要约束，也要处理不确定步骤 |

课件以代码问题求解和软件修复系统说明：组件多、采样量大，不等于控制过程更自主。一个复杂固定流水线仍然可以是工作流。

工程设计也不必把所有步骤交给模型。规则清楚的部分写成程序，模型只处理无法提前枚举的判断，往往更容易测量与调试。

**课件依据：第 55—56 页；混合结构与选型建议为补充。**

## 8. 可靠性、训练、安全与评估 {#challenges}

### 错误会在长流程中累积

可靠性不仅是偶尔成功一次，还包括同题重复运行是否稳定、输入稍变是否失效、失败时能否被理解和恢复。

**补充算例：**假设每个必要步骤独立地以 95% 概率成功，20 步全成功的概率为：

$$
P(\text{全部成功})=0.95^{20}\approx 35.8\%.
$$

独立且同概率只是教学假设，真实步骤有相关性、重试和恢复机制。这一算例说明为什么单步看起来很准，任务级表现却未必可靠，不能用于直接预测实际系统分数。

**课件依据：第 61—63 页；概率算例为补充推导。**

### 训练与长时程问题

长任务的成功反馈稀疏，最终失败很难归因到某一步；采样一条完整轨迹又很昂贵。随着任务推进，上下文不断增长，目标、假设与资料也可能漂移。因此需要同时设计训练数据、状态维护与评估，不能只不断增加提示长度。

### 完成任务不等于遵守边界

智能体可能完成目标，却泄露了不必要资料、接受了外部恶意指令、修改了不应修改的对象，或操纵评估过程。课件的弹窗攻击、隐私与奖励篡改案例都提醒：任务分数无法覆盖全部安全性。

多智能体也不会天然互相制衡。如果系统共享同一漏洞、错误奖励或错误记忆，协作可能放大问题。课件所引具体事故和攻击率依赖研究设置，本篇保留风险机制，不把数字推广到任意系统。

**课件依据：第 61、64—70 页。**

| 应评估的维度 | 要回答的问题 |
| --- | --- |
| 能力 | 能否达成真实目标？ |
| 一致性 | 重复运行是否稳定？ |
| 鲁棒性 | 合理改写与环境变化下怎样表现？ |
| 安全与隐私 | 是否遵守权限与信息边界？ |
| 失败可恢复性 | 能否发现、停止并交接？ |
| 成本 | 时间、调用和预算是否可接受？ |

前五项对应本讲挑战，成本是便于实践的补充评价维度。

## 9. 应用练习与自测 {#practice}

**自编练习：**设计一个只整理公开课程资料的助手。写清可读取的来源、模型负责判断的部分、可用工具、需要保留的记忆、完成证据，以及检索失败或达到预算时的停止条件。

先实现固定的「获取讲义 → 提取要点 → 核对来源 → 输出草稿」，再考虑是否确实需要模型动态重查。两者用同一组资料比较，避免把「更自主」直接当作「更好」。

<details><summary>会调用一次工具，就一定是自主智能体吗？</summary><p>不一定。工具调用可以处在固定流程里。关键在于控制路径中是否有模型依据反馈做出的动态决策，以及它能在哪些边界内行动。</p></details>

<details><summary>Reflexion 保存反思，是否等于做了一次强化学习参数更新？</summary><p>通常不是。这里可以只更新文本经验或外部记忆，用新的上下文影响下一次生成；参数训练是另一个机制。</p></details>

<details><summary>工具参数通过 JSON 校验，为什么还不能直接执行？</summary><p>结构合法不代表目标正确或已经授权。还需要检查参数值、资源范围、权限和动作后果，并处理真实执行结果。</p></details>

<details><summary>如果只能保留本讲一句工程原则，应该是什么？</summary><p>把智能体看成模型、状态、工具、环境、数据与评价共同组成的系统；每项能力都要对应可检查的证据和明确边界。</p></details>
