## 1. 从一条拟合曲线到可执行配方 {#recipe}

扩展规律真正有用时，要回答最终模型多大、训练多少 token、使用什么 batch 与学习率，以及小实验的结果如何迁移。只拟合 N、D 和 loss，还不足以保证大规模训练稳定。

讲义对比两类思路：MiniCPM 利用参数化与 μP 降低宽度变化时的调参负担；DeepSeek 等配方直接对 batch、学习率和计算量的关系进行经验拟合。两者都是带条件的工程路线，不是一个永远正确、另一个永远过时。

**讲义定位：第 2–12、19–30 页。**以下实验模板与符号解释为补充。

## 2. WSD 为什么节省扩展实验 {#wsd}

常规 cosine 日程依赖预定终点。一个只跑到中途的 checkpoint，可能尚未得到学习率衰减带来的收益，直接拿它拟合最终 loss 会失真。

WSD 把训练分为 warmup、stable、decay：先升温，在稳定学习率下训练，再为选定 token 预算接上衰减尾段。不同终点可以共享较长的稳定前缀，减少每个预算点都从头训练的成本。

但共享前缀不等于所有日程完全等价。衰减长度、稳定阶段质量和最终 token 预算都要记录；同一前缀产生的多个终点也并非独立实验，估计不确定性时需考虑相关性。

**讲义定位：第 13–18、22–24 页。**

## 3. μP 试图让什么保持稳定 {#mup}

增加隐藏宽度时，参数数目、激活方差和单次更新对表示的影响会变化。最大更新参数化 μP 希望通过初始化、学习率和参数缩放，让不同宽度网络的激活及其更新保持合适量级，从而让小网络调参更有迁移性。

直观上，如果某层输入维度增加，直接保持每个权重和每个更新的尺度不变，求和结果可能随宽度放大。参数化需要分别考虑输入层、隐藏层和读出层，并与优化器配合；「所有学习率除以宽度」并不是 μP。

迁移的通常是特定参数化下的超参数规律，不是模型权重，也不是任意深度、数据和结构之间的无条件迁移。

**讲义定位：第 44–57 页。**

## 4. 优化器比较为什么特别容易误导 {#optimizer}

不同优化器可能有不同最优学习率、batch、weight decay 和规模依赖。若只给一个优化器精细调参，再给另一个沿用默认值，结论可能只是调参预算不同。

讲义还介绍 Muon 对矩阵更新进行近似正交化的思路。它与 Adam 的状态、参数处理和超参数约定不同，不能只比较同一个数值学习率，也不应把某个小规模优势视作任意规模保证。

| 应固定或记录 | 原因 |
| --- | --- |
| 实际计算与处理 token | 防止把训练更多误认为算法更好 |
| 参数化与初始化 | 决定更新尺度 |
| 调参搜索范围与次数 | 影响比较公平性 |
| 数据、日程与衰减 | 改变终点 loss |
| 多尺度与失败记录 | 检验可迁移性和稳定性 |

**讲义定位：第 31–43 页。**

## 5. 做一轮可靠的小规模扩展实验 {#experiment}

先锁定模型家族、数据版本和验证集，再为每个规模寻找可接受的优化范围。对候选预算覆盖多种 N / D 组合；拟合后，用未参与拟合的较大点检验误差。

补充例子：选 3 个宽度与 3 个 token 预算，先在最小模型检查训练是否稳定，再共享可比的 WSD 前缀。记录每个点的预测 loss、实际 loss 和成本，若误差随规模系统性增加，应优先检查训练不足、参数计数和日程，而非立即增大最终训练。

不要把实验表里只保留的「成功最优点」误当作完整证据。发散、异常梯度与对特定数据的退化，都会影响实际可用的配方。

**讲义定位：全讲案例；本节为补充实践方案。**

## 6. 练习与自测 {#review}

<details><summary>WSD 的 stable checkpoint 能直接当最终收敛结果吗？</summary><p>通常不能，应为对应预算接上合适衰减，并确认与目标训练方案可比。否则可能系统性高估终点 loss。</p></details>
<details><summary>μP 是否意味着从小模型得到的学习率可用于所有模型？</summary><p>不是。迁移依赖具体参数化、宽度缩放、优化器与结构条件，仍需验证读出层、归一化和正则等细节。</p></details>
<details><summary>优化器 A 在 100M 参数时胜出，下一步该做什么？</summary><p>在可比计算和调参预算下增加规模点，检查稳定性、最优超参数变化与外推，而不是直接宣称大模型必然胜出。</p></details>
