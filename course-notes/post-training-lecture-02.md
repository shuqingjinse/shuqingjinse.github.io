## 1. SFT 到底优化什么 {#objective}

**监督微调（Supervised Fine-Tuning）**用输入 $$x$$ 和理想回答 $$y$$ 组成的数据来训练模型。这里 $$x$$ 可以包含系统指令、对话历史、工具结果；$$y=(y_1,\ldots,y_T)$$ 是模型应当生成的回答 token。

自回归模型把整段回答的概率分解为：

$$
\pi_\theta(y\mid x)=\prod_{t=1}^{T}
\pi_\theta(y_t\mid x,y_{<t}).
$$

为了提高示范回答的概率，最小化负对数似然：

$$
\mathcal L_{\mathrm{SFT}}
=-\mathbb E_{(x,y)\sim\mathcal D}
\left[\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})\right].
$$

式中的 $$\theta$$ 是可训练参数，$$\mathcal D$$ 是示范数据集。实际实现还会选择按 token 或按样本归一化；当回答长短差别很大时，归一化方式会影响样本权重。

**单个 token 的直觉：**如果正确 token 的预测概率是 0.1，损失约为 2.303；概率提高到 0.8，损失约为 0.223。梯度更新促使模型在相同前缀下更倾向示范 token。

这与预训练都使用下一 token 的交叉熵有关，但训练分布与目标角色不同。SFT 数据经过任务筛选，并显式包含「输入 → 合适回答」的交互结构。

## 2. Teacher forcing 与损失区域 {#forcing}

### Teacher forcing：训练时给正确前缀

假设示范回答是「答案是 42」。训练预测「42」时，前面给的是示范里的「答案是」，而不是模型自己刚生成的一段错误文字。这称为 teacher forcing。

它能高效计算所有位置的监督损失，但训练时主要看到正确轨迹。推理时如果前面生成错了，后续上下文就偏离示范分布；这也是为什么单纯拟合示范并不自动解决所有错误恢复问题。

### 输入要看见，损失可以不计算

常见的指令微调只在助手回答位置计算损失：

| 区域 | 是否提供给模型 | 是否作为预测目标计入 loss |
| --- | --- | --- |
| 系统指令、用户问题 | 是 | 通常否 |
| 助手回答 | 是，训练时移位预测 | 是 |
| 批处理填充部分 | 有占位，但需正确设置 attention mask | 否 |

在许多 PyTorch / Transformers 训练流程中，令不参与监督位置的 label 为 **-100**，交叉熵就会忽略这些位置。这里的忽略是**不计算该位置预测目标的损失**，不是切断用户问题对回答的条件作用。

多轮对话可监督所有助手回合，也可只监督最后一轮；工具调用数据还需要决定哪些消息属于需要模型学习生成的行为。必须检查真实 batch 中的 labels，不能只凭数据列名推断。

> **实现细节：**TRL 对普通语言建模数据和 prompt–completion 数据的默认 loss 区域可能不同。「传入 messages」不等于自动只训练 assistant。需要显式选择数据格式与配置，核对模板是否支持助手区域标记。[SFT 文档](https://huggingface.co/docs/trl/v0.19.1/sft_trainer)

## 3. 聊天模板与终止符 {#templates}

应用里是消息列表，模型实际读入的是一串 token。**Chat template**负责把角色和内容转成模型预期的序列，例如「用户开始标记 → 问题 → 助手开始标记 → 回答 → 回合终止标记」。

以下是抽象示意，不是可以替换任意模型模板的通用格式：

~~~text
[SYSTEM] 你是一个简洁的助手。
[USER] 17 + 25 等于多少？
[ASSISTANT] 42。[END_OF_TURN]
~~~

训练与推理要在角色标记、空白、特殊 token 与结束方式上保持一致。若训练使用一种模板，推理突然改用另一种，模型可能续写用户消息、输出多轮对话，或不知道何时停止。

用 tokenizer 的 **apply_chat_template** 比手写拼接更可靠。推理通常添加助手回答的开头，训练完整对话则已有回答，不应重复添加。

还要分清：

- **EOS / 回合结束符**：告诉模型这段生成何时应结束，具体定义随模型变化。
- **PAD**：把不同长度的样本补成批次；填充区域应从 attention 或损失计算中恰当排除。
- **最大长度截断**：如果只保留了问题，把答案切掉了，模型几乎没有有效监督；若结束符总被截断，还可能影响停止行为。

没有 pad token 时，有的模型会用 EOS 兼任，但不能简单按「所有等于 EOS 的 token 都忽略」构建标签，否则真实终止符也可能丢失监督。应依据填充位置构造 mask。[聊天模板文档](https://huggingface.co/docs/transformers/chat_templating)

## 4. 好数据比多训几轮更关键 {#quality}

示范不仅告诉模型「答案是什么」，还传递语气、长度、推理风格、是否承认不确定、是否使用工具等行为。如果数据同时包含「只给答案」与「必须写长解释」，又没有条件区分，训练目标会互相拉扯。

整理数据时，可以按以下顺序处理：

1. 定义真实任务与验收条件，先写少量代表性样例。
2. 删除错误、无信息、重复和角色错乱的对话。
3. 检查各类任务、语言与长度的比例，避免少数模板淹没其他场景。
4. 在去重之后切分数据，隔离测试集，保留困难案例。
5. 训练前打印序列和 loss mask，确认模型究竟在学什么。

**过拟合**不仅表现为背答案，还可能表现为固定开场白、重复格式或在不需要时也长篇解释。增加 epoch 会增加对同一批示范的拟合，不能弥补示范本身缺少多样性。

## 5. 全参数微调与 LoRA {#lora}

全参数微调更新模型中所有允许训练的权重。LoRA 则冻结原权重，为选定线性层增加一个可训练的低秩增量。

设原权重 $$W_0\in\mathbb R^{d_{\text{out}}\times d_{\text{in}}}$$，令：

$$
W'=W_0+\frac{\alpha}{r}BA,\qquad
A\in\mathbb R^{r\times d_{\text{in}}},\quad
B\in\mathbb R^{d_{\text{out}}\times r}.
$$

因此 $$BA$$ 的维度与 $$W_0$$ 相同。rank $$r$$ 远小于输入、输出维度时，可训练参数从 $$d_{\text{out}}d_{\text{in}}$$ 降到 $$r(d_{\text{in}}+d_{\text{out}})$$。

**补充算例：**一个 $$4096\times4096$$ 的权重有 16,777,216 个参数；设 $$r=8$$，两个低秩矩阵共有 65,536 个参数，为该权重参数量的约 0.39%。这只统计一个被适配的矩阵，不能直接当成整个模型的显存节省比例。

| 方式 | 更新内容 | 主要取舍 |
| --- | --- | --- |
| 全参数微调 | 大量或全部模型权重 | 可调空间大，梯度和优化器状态开销高 |
| LoRA | 指定层的低秩适配矩阵 | 参数少，需选择目标层、rank 与缩放 |
| QLoRA | 量化保存基础权重，训练低秩适配器 | 进一步减少权重存储，需匹配量化与计算配置 |

LoRA 减少可训练参数及相关状态，但前向、反向仍需经过基础模型；激活、序列长度与批量仍会影响内存。它也不是自动防止遗忘的保证。推理时可保留独立适配器，或在兼容的精度与部署方式下合并权重。[LoRA 原始论文](https://arxiv.org/abs/2106.09685)、[QLoRA 原始论文](https://arxiv.org/abs/2305.14314)

## 6. 常见误区与自测 {#review}

**「SFT 只教格式，不会教新知识」**过于绝对。SFT 可以让模型学习数据中的信息与模式，只是可靠记忆、泛化和持续更新并无自动保证。

**「SFT 训练越久越好」**同样不成立。需要同时看验证表现、任务指标与一般能力；模型容量、学习率、数据质量和数据量共同影响结果。
